4. Google Business : tuto pas à pas

But : (1) un accès gestionnaire à leur fiche Google, (2) le Place ID, (3) une clé API pour afficher automatiquement la note et les avis. Le code est prêt (api/reviews.js) : il manque 2 variables chez l'hébergeur.

Étape A : obtenir un accès à la fiche (sur place, avec le propriétaire)

  1. Le propriétaire se connecte avec le compte Google de la fiche, sur business.google.com.
  2. Fiche « Hôtel Restaurant Les Carillons » → Paramètres de l'établissement (ou « Autorisations ») → Utilisateurs → Ajouter.
  3. Il saisit ton adresse Gmail, choisit le rôle Gestionnaire, envoie l'invitation.
  4. Tu acceptes l'invitation depuis le mail reçu ou depuis business.google.com.
Si personne ne sait qui gère la fiche : chercher l'hôtel sur Google Maps → « Gérer cet établissement » / « Revendiquer » → validation par téléphone, courrier ou vidéo. Prévoir quelques jours : à lancer dès jeudi.

Étape B : vérifier la fiche avec eux (5 min)

  • Nom exact de la fiche :
  • Horaires à jour (hôtel / restaurant) · jours de fermeture annuelle
  • Téléphone 05 65 63 14 75 et site web https://www.lescarillons.fr
  • Catégorie principale + catégories secondaires (hôtel, restaurant, location de meublés)
  • Photos récentes · lien de réservation · description à jour
  • Qui répond aux avis ?

Étape C : trouver le Place ID

  1. Aller sur developers.google.com/maps/documentation/places/web-service/place-id (outil « Place ID Finder »).
  2. Taper « Hôtel Restaurant Les Carillons Cransac », cliquer sur la bonne fiche.
  3. Noter le Place ID (commence par ChIJ…) :

Étape D : créer la clé API Google (chez toi, avec le compte Google de ton choix)

  1. console.cloud.google.com → Nouveau projet → nom : « Les Carillons ».
  2. Facturation : associer une carte bancaire (exigée par Google même pour un usage gratuit). Idéalement le compte de l'hôtel ; sinon le tien, à transférer plus tard.
  3. API et services → Bibliothèque → « Places API (New) » → Activer (pas l'ancienne).
  4. Identifiants → Créer des identifiants → Clé API. Copier la clé.
  5. Restreindre la clé : « Restrictions relatives aux API » → cocher uniquement Places API (New). (Pas de restriction par site web : l'appel part du serveur de l'hébergeur.)
  6. Garde-fou : Facturation → Budgets et alertes → budget de 5 € avec alerte à 50 % et 100 %.
Les avis sont mis en cache 24 h : quelques dizaines d'appels par mois, normalement dans le quota gratuit de Google. Vérifier la grille tarifaire actuelle sur developers.google.com/maps/billing-and-pricing.

Étape E : brancher chez l'hébergeur

Le site de démonstration est sur Vercel ; à la mise en ligne il passera chez OVH. Les étapes ci-dessous valent pour Vercel (démo) ; chez OVH, la clé et le Place ID vont dans le fichier api/config.php sur le serveur (voir docs/HEBERGEMENT-OVH.md).

  1. vercel.com → projet du site → Settings → Environment Variables.
  2. Ajouter GOOGLE_PLACES_API_KEY (clé de l'étape D) et GOOGLE_PLACE_ID (Place ID de l'étape C).
  3. Cocher Production → Save → Redeploy.
  4. Test : ouvrir https://www.lescarillons.fr/api/reviews : du JSON avec rating et reviews. Page vide (204) = variables absentes ou pas redéployé ; erreur 502 = clé mal restreinte ou API non activée.

Formulaires (Web3Forms)

  1. web3forms.com → saisir l'adresse de réception (lescarillons12@orange.fr).
  2. Une clé d'accès arrive par mail à cette adresse : quelqu'un de l'hôtel doit la lire sur place jeudi.
  3. Chez l'hébergeur : variable VITE_WEB3FORMS_KEY = cette clé, puis redéployer (la clé est lue à la construction du site).
  4. Test : envoyer le formulaire de contact du site et vérifier la réception. Sans clé, le formulaire ouvre la messagerie du visiteur : il marche, mais moins bien.
